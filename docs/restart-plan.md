# 重建基线与后续顺序

2026-11-19。本轮范围为保存旧项目、建立参考库、搭建可运行且可版本管理的新起点。新的启动页不代表新游戏已经实现；旧 T01—T20 状态也不自动映射成新项目完成项。

## 已采用的基础选择

- 使用本机 Node.js 24.12.0、npm 11，严格 TypeScript 5.9.3。程序不加载任何旧代码或第三方 Java 参考源码。
- 基础程序只用 Node 标准库，提供本地启动页和健康接口；运行依赖为零，开发依赖锁定到 `package-lock.json`。
- 旧代码、全部文档、素材、存档、训练记录及旧依赖集中在 `legacy/2026-11-19/`。用清单验证冻结约定；不通过 chmod/ACL 修改旧文件属性，不宣称操作系统强制只读。
- Forge 与 TripleA 的 AI 参考源码按固定提交逐文件下载，完整仓库、发行版、图片和地图包均不下载。参考源码与新产品依赖分离。
- 新公开库使用独立历史；本机原 Git 对象和其他 worktree 保留，不推送旧历史。
- 新基础环境尚不需要 Python、CUDA、Java、Electron、React 或模型权重。将来确有需求再引入相应环境及检查，不宣称这些组件已经配置。

## 下一阶段建议

| 顺序 | 内容 | 可核验的出口 |
| --- | --- | --- |
| R1 | 确定首版规则范围：基础/全面战争、信息模式、国家/地图/卡牌真值来源 | 版本化规则清单、明确的范围与来源、代表性合法/非法场景 |
| R2 | 纯规则内核和确定性对局 | 固定种子重放一致；动作、响应/付款/取消顺序、积分守恒、存档身份均可测试 |
| R3 | 授权观察与统一 AI 接口 | 改变不可见信息不改变观察；合法动作和唯一选择共享同一规则源 |
| R4 | 最小可玩界面和规则 AI | 人机可完成整局；记录选中的真实动作；迁移的卡牌逐类验收 |
| R5 | 小规模只读回放和恢复 | 字节预算内读回真实帧，缺失明确显示；中断恢复与正常运行有对照 |
| R6 | 搜索/学习 AI 与桌面交付 | 再选择技术和依赖；模型身份、实际推理、能力评测、内存与打包分别通过 |

这里给出后续工作的依赖顺序，不自动开始实现新规则或恢复旧的长时间评测。
