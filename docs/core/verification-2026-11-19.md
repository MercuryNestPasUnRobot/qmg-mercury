## 2026-11-20 封闭对象池复验

| 场景 | 观察结果 |
| --- | --- |
| 同一回合连续三次触发 | 无限次副本以同一 ID 结算三次，一次性副本结算一次后回池。两个限次副本分别结算一次，第三次触发没有可用副本 |
| 回合末归还 | 两个已用副本各自将配对的隐藏响应从对象池移入响应区。符合条件时，响应依次进入结算区，各将原副本移回可用区，再各自回池。下轮可以重复使用 |
| 结算中断和信息边界 | 在首个响应进入结算区后保存，重新执行与日志重放得到相同的状态及链头。对手只看到响应区的数量，无法查看隐藏响应或池内清单 |
| 对象数量和身份 | 对象池耗尽时操作记录失败。额外 ID、缺失 ID、篡改定义和移除整个池均被拒绝。随机指令序列逐步核对开局 ID 及全部移动的双端位置 |
| 旧存档实际迁移 | 用先前提交 `dcc8456` 生成格式 1 快照和含冷却副本的 JSONL 日志，交给当前版本续玩。下一回合以原 ID 归还副本，重新读档状态一致，原日志前缀逐字节保留 |
| 本地整体验证 | `npm run check` 通过，含 86 项 Python Core 测试、4 项 Node 测试、1,725 个归档文件及 347 个上游文件。无界面演示完成 8 条记录的重放 |

## 统一操作入口复验

- 人类和 AI 的席位接口都拒绝直接转移对象及附带目的地的出牌请求。提交同一个合法建造请求和目标选择时，两者得到相同的移动记录、局面和完整日志。
- 已失效的目标不会发出可供响应的宣告。嵌套响应移除来源能力时，Core 清理该能力的未完成宣告。存档恢复后执行该分支与完整日志的回放一致。
- AI 通过席位视图完成候选模拟。无法表示的隐藏对象及超出预算的原子结算只影响各自候选。手牌潜力使用与出牌入口相同的限制和确切目标检查。
